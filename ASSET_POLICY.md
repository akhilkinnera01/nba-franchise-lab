# Asset Policy

## Scope

Assets include logos, photos, screenshots, charts, illustrations, badges, icons, exports, and generated images used in code, docs, tests, or marketing surfaces.

## Requirements

- Every committed asset must have a documented source and usage right.
- Prefer original, self-created, or permissively licensed assets.
- Keep attribution requirements with the asset or in the relevant doc when the license requires it.
- Use demo-safe assets for public examples, screenshots, and README imagery.
- Store only assets that are safe to publish in a public repository.

## Prohibited Assets

- Unlicensed or unclear-rights images, logos, screenshots, or artwork.
- Paid or restricted assets copied from tools, sites, or feeds without redistribution rights.
- Screenshots that expose credentials, private data, or restricted source content.
- Assets that depend on a contract, login, or private entitlement unless the agreement explicitly allows public storage.

## Review Gate

- If rights are unclear, do not commit the asset.
- If the asset is only approved for local or private use, keep it out of git and note the limitation.
- If an asset is replaced, remove the old asset unless it is still required and still rights-cleared.
